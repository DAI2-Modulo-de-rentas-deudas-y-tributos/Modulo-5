Fecha de inspección: 2026-10-28
Base inspeccionada: `c8a9954f0ca3d3dcd863463f8f159166280062a8`
Alcance: dependencias Maven del backend y precondiciones de CVE-2026-47834/CVE-2026-47860.

El `dependency:tree` se ejecutó con Maven Wrapper en `backend/`. La inspección del POM modificado sin commit en el worktree `release/m5-pre-core-final` mostró que Spring Boot 3.5.16 administra `spring-data-jpa:3.5.13` y `spring-amqp`/`spring-rabbit:3.2.12`; ambas versiones también están dentro de los rangos afectados. Por lo tanto, ese cambio de BOM no soluciona estos CVE.

## Condiciones de explotación revisadas

### CVE-2026-47834 — Spring Data JPA

El aviso de Spring requiere simultáneamente que el servicio acepte `Sort` no confiable y sin sanitizar, que lo use contra un método de repositorio con consulta nativa y parámetro `Sort` o `Pageable`, y que la base acepte sintaxis SQL no ASCII.

En el código revisado, `OutboxRepository.findPublishable(Pageable)` es el único método de consulta nativa encontrado. Sólo lo invoca `OutboxPublisher.publishPending()` con `PageRequest.of(0, 50)`, sin orden dinámico ni datos HTTP. Los `Pageable` expuestos por controladores pasan por `FilteredQueryService`, que valida los nombres de orden contra una lista permitida y construye consultas Criteria, no la consulta nativa del Outbox. La ruta de entrada vulnerable del aviso no se encontró en esta revisión.

Esto es una evaluación de precondiciones del código actual; no convierte la versión afectada en versión corregida y debe revisarse si se agregan consultas nativas ordenables.

### CVE-2026-47860 — Spring AMQP

El aviso describe agotamiento de memoria cuando un atacante publica un cuerpo comprimido en una cola consumida por una aplicación que habilitó la descompresión de mensajes.

`CoreRabbitMqConsumer` existe sólo con `rentas.broker-adapter=rabbitmq` y `autoStartup` es `false` por defecto. No se encontró `afterReceivePostProcessors`, `GZipPostProcessor`, ni configuración de compresión/descompresión en fuentes o configuración del backend. La configuración de permisos de publicación del broker externo no fue auditada y no se verificó ningún Core real; por ello no se afirma que el riesgo de la dependencia esté resuelto.

## SCA ejecutada

Se ejecutó OSV-Scanner oficial `v2.7.0` en un contenedor Docker efímero contra `backend/pom.xml`, con resolución Maven nativa. La herramienta reportó 23 paquetes con 94 advisories conocidos: 11 críticas, 35 altas, 38 medias, 9 bajas y 1 sin severidad. La salida consultada no incluyó los IDs CVE-2026-47834 ni CVE-2026-47860; ambos se verificaron directamente contra los avisos oficiales de Spring, que son la fuente primaria para sus rangos y condiciones.

Comando reproducible desde PowerShell, ajustando la ruta del worktree:

```powershell
docker run --rm -v "${PWD}:/src" ghcr.io/google/osv-scanner:v2.7.0 `
  scan source /src/backend --data-source native --format vertical --verbosity warn
```

La cantidad global del scanner no es una lista de falsos positivos ni un análisis de explotabilidad. Requiere triage de cada paquete/advisory antes de utilizarse como criterio de salida.

## Remediación propuesta

No se hizo override aislado de `spring-data-jpa` o `spring-amqp`: mezclar líneas mayores con Boot 3.5 puede romper la alineación del BOM y no fue probado.

- Mantener Boot 3.5 implica que las versiones corregidas de su misma línea citadas por Spring (`spring-data-jpa` 3.5.14 y Spring AMQP 3.2.13) son Enterprise Support Only.
- Las correcciones OSS citadas por Spring están en líneas 4.x (`spring-data-jpa` 4.0.7/4.1.1; Spring AMQP 4.0.5/4.1.1). El BOM oficial de Boot 4.0.9 administra Spring Data JPA 4.0.8 y Spring AMQP 4.0.6, ambos superiores a los mínimos OSS corregidos, y Boot 4.0 requiere Java 17 como mínimo.
- La opción OSS coherente es evaluar una actualización completa y alineada a Spring Boot 4, no cambiar dos artefactos en forma aislada. Es un salto mayor y necesita PR/ticket con pruebas de regresión completas y revisión del equipo antes de adoptarse.

Mientras se decide, mantener cerradas las precondiciones revisadas: no pasar orden proporcionado por usuarios a consultas nativas y no activar procesadores de descompresión de mensajes para colas no confiables. Estas medidas reducen el camino de explotación actual, pero no reemplazan actualizar las dependencias afectadas.

## Veredicto

Las precondiciones concretas de ambos avisos no se encontraron activas en el código inspeccionado, pero eso no sustituye la actualización a versiones corregidas. Se recomienda decisión del equipo sobre una actualización alineada a Spring Boot 4 o el uso de soporte Enterprise en la línea Boot 3.5.
